执行多步/批量任务时**默认沉默工作**：工具调用之间不输出"找到了"/"line X 完成"/"继续处理剩余 N 项"/"WRef 不是 DOM 属性"这类中间状态文字；只在三种情形开口——任务完成（一次性结果摘要）、遇到阻塞（卡点 + 需用户决策）、歧义/异常（请用户确认方向）。

**Why:** 2026-05-17 用户在做 Starling 短剧 polish 批处理时截图反馈：CLI 里看到 Claude 一行行汇报每个 playwright 调用的进度（"Line 29 找到了"、"继续处理剩余 11 行"），干扰他检查最终结果。他明确说"怎么才能让 CLI 在工作中不用这样一直报告进度，直接输出结果让我检查"。

**How to apply:**
1. 已通过 `~/.claude/output-styles/quiet.md` + settings.json `"outputStyle": "Quiet"` 永久启用 Quiet 风格作为主防线；这条 memory 作为兜底，即使 Quiet 风格未生效（自定义 output style 加载失败/切换走了）也要遵守同样原则
2. 适用场景：Starling 短剧逐行 polish、Unity 批量改字段/预制体、批量文件改写、跑测试套件等明显是"批处理"的工作
3. **不适用**：用户问开放性问题（"怎么办"、"分析一下"、"为什么"）时正常作答；用户明确说"详细说明"/"边做边讲"时切换为解释模式
4. 完成时输出格式：1-3 句话或一个短列表，列出改了什么 / 产出路径 / 关键点；不复述执行过程
5. 安全确认仍然要做（破坏性操作、对外发送等），不能为了"安静"跳过；错误和警告要立即清晰报告，不能藏在最终摘要里
